# 十案例数据分包：哪些适合开发 REFMAC，哪些适合开发 Buccaneer

结论先行：十例按“精修难点”和“建图难点”各取五例，做成两个互不共用案例的
自包含数据包，可直接拷到另一台机器开发与评测。

| 包 | 案例 | 体积 |
| --- | --- | --- |
| `bundles/refmac_set/` | 5HHK, 6ZPP, 7ENM, 7TBS, 7TJ1 | 13 MB（tar 3.8 MB） |
| `bundles/buccaneer_set/` | 3O2E, 5D9D, 6HF7, 7E1D, 7TFQ | 17 MB（tar 8.6 MB） |

两个包各自带 `README.md`（验收口径）、`manifest.json`（逐文件 sha256）和
每例的 `meta.json`；`bundles/SHA256SUMS.txt` 是 tar 包的校验值。

## 1. 判据

**REFMAC 类程序**考的是“给定一个大致正确的模型，能不能把它精修到沉积水平”。
所以选案例看的是：分辨率（决定几何/ADP 精修的权重）、空间群与 ASU 拷贝数
（NCS、非晶体学对称的处理）、体系大小（迭代成本）、溶剂分数（溶剂模型与
整体 B），以及**起点质量的分层**——纯精修收敛、收敛半径、真实 SAD 起点三条线
必须分开测，否则分不清“靶函数对”和“起点好”。

**Buccaneer 类程序**考的是“给定一张实验图，能建出多少正确的主链”。
所以选案例看的是：图质量（FWT/PHWT 与真值密度的 CC）、溶剂分数（图越平、
噪声越大）、ASU 拷贝数（多拷贝会互相抢密度）、体系大小（迭代成本），
以及覆盖率的分布——要有能建全的、也要有建不全的，才能测“从坏图里救回多少”。

这两组要求并不重合，所以按 5/5 分而不是让每例两用：分线之后，任何一套上的
调参都不会污染另一套的评测。

留下的碎片链，故 6HF7、7TJ1 偏低）。

## 3. 为什么这样分

REFMAC 线的五例把精修的几个难点分别隔离出来：

- **5HHK**：1.40 Å、1407 残基、双拷贝。最高分辨率下键长/键角/ADP 的权重最敏感，
  双拷贝还能测 NCS 约束。它是这套数据里唯一能对标“REFMAC 几何质量”的案例。
- **6ZPP**：1.50 Å 单链 337 残基，跑一轮只要几十秒，适合高频迭代。
- **7ENM**：1.70 Å、溶剂仅 0.30、251 残基，最容易收敛，用来当“靶函数实现对不对”
  的基线；如果这一例都收敛不了，问题在实现而不在数据。
- **7TBS**：I222、溶剂 0.51，专门测溶剂模型与整体 B；高溶剂下溶剂参数错了
  R-free 会明显劣化。
- **7TJ1**：2.10 Å、3 拷贝、595 残基，最低分辨率端，测几何权重与 NCS 的平衡。

Buccaneer 线的五例把图质量从好到差排开，并且刻意保留“建不全”的样本：

- **5D9D**（CC 0.73，98%）：顺利基线，先证明程序能建全。
- **6HF7**（CC 0.68，91%，3 拷贝，55% 溶剂）：多拷贝 + 最高溶剂，测拷贝分配。
- **7TFQ**（CC 0.64，94%，R 0.325）：中等图，能建全但 R 偏差大，测迭代重建。
- **7E1D**（CC 0.62，86%）：覆盖最不全，测“建到一半”的行为。
- **3O2E**（CC 0.53，94%）：图最差的一端，测低信噪比下的主链追踪。

注意 3O2E 与 7E1D 的战役 R（0.41 / 0.37）差，主要来自相位质量与精修不足，
不是建模失败：它们的建出 CA 分别有 94% / 86% 落在真值 1 Å 内。这也是为什么
建模线用“覆盖率 + CA RMSD”而不是 R 作为主指标，R 只作辅助。

## 5. 数据清洗与 free-R 约定（两包都做了）

源 `-sf.mtz` 用 NaN 表示“未测量”，不是缺行；OASIS 的中间文件把这些 NaN 带了
下来（`native.mtz` 2–3%，`experimental.mtz` 最多 26%，`map_phases.mtz` 只有
3O2E 有 40 行）。第一版包直接复制了这些文件，结果任何朴素读入都会把 NaN 带进
密度图和 R——我自己的校验脚本就是这样得到 `R = nan` 的。

现在 `make_bundles.clean_mtz()` 做两件事：

1. **删掉 `F`/`SIGF`/`FWT`/`PHWT`/`F±` 非有限的整行**，逐例条数写进
   `meta.json.data_cleaning`。7ENM 删 857/11057 行（`native.mtz`），7E1D 的
   `experimental.mtz` 删 3439/12507 行——这些是 `I(-)` 未测量、`F=sqrt(I)` 无
   定义的行，本来就不能参与定相（战役实际定相用的是 10441 条，与删除后的
   9068 条同量级）。
2. **把 `FreeR_flag` 重新编码为 0=work、1=free**。战役文件是 0=test set，
   REFMAC 必须加 `FREE 0` 才对（战役的 `refmac.log` 里确实是
   `FREE 0` / `Number of "free" reflections 521`）；本包改成 REFMAC/Phenix 的
   默认约定，test set 集合不变，stock 程序不加关键字即可。free 比例 4.8–5.2%。

副作用：R 的分母比战役略小（多数 <1%，5HHK 3%、7ENM 8%），战役 R/R-free 仍是
REFMAC 在原始行集上算的，两者相差 0.01 量级。

## 6. 坐标系与手性（必须注意）

十个案例的 SAD/DM 图与沉积结构**同一手性**，但原点差一个平移，且 ASU 内的
拷贝可能对应不同的空间群算符与相邻晶胞。实测同手性密度 CC 0.53–0.73，
反手只有约 0.03，所以没有一例需要镜像。

`work/frame_fit.py` 的做法：先用 FWT/PHWT 图与模型密度的 FFT 互相关求平移，
再对每个空间群算符 + 格点平移逐链匹配，取使“战役模型 CA 最近邻中位数”最小的
组合。十例最终中位数 0.06–0.23 Å、86–99% 的 CA 落在 1 Å 内，与战役 R 一致，
说明这个坐标系是可信的（早期用 `PHIB/FOM` 建图得到的 CC 0.01–0.09、9/10 判为
镜像的结论是错的，已废弃）。

包内已按用途处理好：Buccaneer 的 `truth_model.pdb` 在图坐标系，REFMAC 的
`start_model_sad_built.pdb` 在沉积坐标系，两边都能直接算 RMSD。

## 7. 复现

```bash
./.conda-unified/bin/python work/bundle_tencase.py   # 扫描战役，写 work/tencase_inventory.json
./.conda-unified/bin/python work/frame_fit.py        # 求坐标系，写 work/tencase_frames.json
./.conda-unified/bin/python work/make_bundles.py     # 打包，写 bundles/*/
cd bundles && tar -czf refmac_set.tar.gz refmac_set && tar -czf buccaneer_set.tar.gz buccaneer_set
```

输入是 `/Volumes/Fast_4T/Deepseek-Oasis/work/exp/tencase_gui_20261110` 下的战役
输出和 `/Volumes/For_data/IPCAS-test/100_SAD_data` 下的原始数据；换机器时只需
拷贝两个 tar 包，不需要 OASIS 或 CCP4。

## 8. 已知局限

- `7TFQ` 的战役目录里没有 `refined_heavy.pdb`，所以包里没有 `heavy_sites.pdb`；
  需要重原子位点时只能从 `experimental.mtz` 自行找。
- `6HF7` 的战役模型除 3 条主链（192/191/190 CA）外还有 3 段 6–16 个 CA 的碎片
  链，`7TJ1` 除 4 条主链外还有 3 段 7–12 个 CA 的碎片（`meta.json` 的
  `chain_map` 里 `truth_chain: null`）。`build_quality` 把这些碎片也算进分母，
  所以 6HF7 显示 91%、7TJ1 显示 90%，只看主链则是 95.5% / 94.8%。
- `3O2E` 的战役模型本身就是碎片：A 63 + B 9 + C 6 = 78 个 CA 覆盖真值 86 个
  （91%），三段都落在同一条真值链上（B 与 A 的中位数 0.51 Å），所以它是
  “建得对但不完整”，不是“建错”。
- `truth_model.pdb` 的坐标可能落在相邻晶胞（为与战役模型逐原子可比而保留了
  格点平移），直接看会“出格”，但 RMSD/覆盖率不受影响。
- 两个包都不含衍射图像，只有合并后的 MTZ；不覆盖“从图像到 MTZ”的环节。
